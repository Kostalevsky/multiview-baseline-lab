# multiview-baseline-lab

Лаборатория выбора ракурсов OBJ-моделей и визуального сравнения baseline-методов. Blender рендерит изображения; Python выбирает виды, создаёт коллажи и сохраняет истории отдельных методов.

## Структура

- `run.py` — CLI; `comparison.py` — визуальное сравнение коллажей.
- `baselines/` — методы выбора и сохранения результатов.
- `rendering/` — скрипты Blender для рендера и подготовки геометрии.
- `utils/blender.py` — поиск Blender через `BLENDER_PATH`, PATH и стандартные пути ОС.
- `examples/models/` — `test.obj`, `part_spinner.obj`, `part_skull.obj`.
- `scripts/` — оболочки запуска для Bash и PowerShell.
- `outputs/` — локальные артефакты; вся папка игнорируется Git.

## Реализованные методы

| Метод | Поведение | Доступ через CLI |
| --- | --- | --- |
| CAD2Tech | 28 кандидатов: 20 случайных с seed 42 и 8 круговых; RGB-признаки 64×64 → Isomap → выбор 6 разнесённых точек | `cad2tech` |
| ISO Orthographic | 6 фиксированных ортографических видов: front, back, left, right, top, bottom | `iso` |
| Canonical | 8 фиксированных ортографических видов: ±X, ±Y, ±Z и 2 изометрических | `canonical` |
| MVCNN Views | 12 перспективных видов с шагом азимута 30° или 6 через один с шагом 60°. Подъём камеры 30° | `mvcnn12`, `mvcnn6` |
| GIFT-inspired Fibonacci | 6 фиксированных перспективных RGB-видов по всей сфере, midpoint Fibonacci sampling | `gift` |
| ISO Isometric | 4 ортографических изометрических вида | Класс `ISOIsometricBaseline`; в CLI не подключён |
| VLM Iterative | 32 кандидата; последовательный выбор 6 видов через Qwen и финальная проверка возможной замены | `vlm_iterative` |
| VIN-NBV Oracle | 120 камер на трёх полусферических оболочках; случайный первый вид, ближайший второй, затем greedy-выбор по геометрическому RRI | `vin_nbv` |

VIN-NBV реализован как адаптированный oracle-вариант: выбор использует полную GT-геометрию объекта и видимые точки кандидатов. Он не является подтверждённым точным воспроизведением статьи или методом, работающим без доступа к GT. Значения по умолчанию: 6 видов, seed 42, 100 000 GT-точек, разрешение видимости 192, порог покрытия 0,01.

`--baseline all` запускает **CAD2Tech, ISO Orthographic, VIN-NBV Oracle и Canonical**, затем создаёт `compare.png`. VLM Iterative и ISO Isometric в этот режим не входят.

MVCNN Views использует схему камер из §3.1 [статьи MVCNN](https://www.cv-foundation.org/openaccess/content_iccv_2015/papers/Su_Multi-View_Convolutional_Neural_ICCV_2015_paper.pdf) и настройки перспективного рендера CAD2Tech. Оба режима работают без обученной сети. Для `mvcnn6` берутся камеры с индексами 0, 2, 4, 6, 8 и 10 из `mvcnn12`. Модель должна быть ориентирована вертикально по Z после импорта OBJ в Blender. Наборы из 6 и 12 кадров учитываются как разные бюджеты изображений.

```bash
.venv/bin/python run.py --baseline mvcnn12 --input examples/models/part_spinner.obj
.venv/bin/python run.py --baseline mvcnn6 --input examples/models/part_spinner.obj
```

Каждый режим сохраняет кадры в `selected/`, подписанный коллаж и `metadata.json` в `outputs/<модель>/<режим>/`. Для повторного запуска укажи новый каталог через `--output-dir`.

При сборке `--baseline all` готовые `mvcnn12/collage.png` и `mvcnn6/collage.png` из каталога модели автоматически добавляются в итоговый коллаж. Основной проверочный объект — `part_skull.obj`. Расширенное сравнение черепа сохранено отдельно в `outputs/part_skull/compare_mvcnn.png`.

### GIFT-inspired Fibonacci-6 и источники

В §2.1 оригинальной [статьи GIFT, CVPR 2016](https://songbai.site/files/GIFT_CVPR.pdf) описаны камеры на сфере и depth-проекции. В экспериментах используются 64 вида, далее признаки извлекаются обученной CNN для поиска форм. Конкретная Fibonacci-схема размещения в статье не указана.

Наш вариант для сравнения ракурсов использует 6 RGB-кадров, перспективный Blender-рендер CAD2Tech/MVCNN и нормализацию по bounding box. Число 6 выбрано для общего бюджета изображений лаборатории. Сферическая Fibonacci-сетка — самостоятельный выбор для детерминированного покрытия сферы; научный источник по таким сеткам — [Keinert et al., Spherical Fibonacci Mapping, 2015](https://doi.org/10.1145/2816795.2818131). Название в коллаже и metadata — GIFT-inspired Fibonacci.

Для индексов i=0,…,5 задаются z=1−2(i+0.5)/6, азимут i·π(3−√5) по модулю 2π и возвышение asin(z). Камеры находятся на радиусе 3, направлены в центр нормализованной модели. Ось Z — вертикаль Blender после импорта OBJ. Выборка, число кадров, RGB и профиль нормализации относятся к адаптации лаборатории. Код реализован по описанию и формуле, авторский код GIFT не использован.

```bash
.venv/bin/python run.py --baseline gift --input examples/models/part_skull.obj
```

Результаты сохраняются в новом каталоге `outputs/part_skull/gift_fibonacci6/`: `selected/`, `collage.png`, `metadata.json` с камерами, источниками и принятыми адаптациями. Для повторного запуска нужен новый `--output-dir`. Готовый GIFT-inspired коллаж автоматически включается при сборке `--baseline all`. Расширенное сравнение черепа со всеми сохранёнными методами — `outputs/part_skull/compare_gift.png`.

Итоговые плитки CAD2Tech подписаны номером выбора и индексом кандидата; VIN и VLM — также азимутом и высотой камеры в градусах. ISO и Canonical показывают номер и название фиксированного вида. Номера плиток начинаются с 1, индексы кандидатов — с 0; для VLM порядок отражает итоговый набор после возможной замены.

2026-11-01: сравнение только для skull пересобрано из существующих изображений в `outputs/part_skull/annotated_2026-11-01/compare.png`, с Canonical и подписями. Исходные результаты сохранены; рендер, выбор ракурсов и API-вызовы повторно не запускались. Индексы CAD2Tech восстановлены сопоставлением SHA-256 выбранных файлов с кандидатами; соответствие выбранных VIN-изображений индексам истории также проверено по SHA-256. Источник: локальные изображения и metadata; сведения о подписях — `labels.json` рядом с новым коллажем.

Команды выполняются из корня проекта с существующей `.venv`:

```bash
# Справка: проверена при обзоре
.venv/bin/python -B run.py --help

# Запуски экспериментов: приведены по коду, при обзоре не выполнялись
.venv/bin/python run.py --baseline iso --input examples/models/part_spinner.obj
.venv/bin/python run.py --baseline cad2tech --input examples/models/part_skull.obj
.venv/bin/python run.py --baseline vin_nbv --input examples/models/part_skull.obj
.venv/bin/python run.py --baseline all --input examples/models/part_skull.obj
bash scripts/run_all.sh

# Требует явного поручения на API-вызовы
.venv/bin/python run.py --baseline vlm_iterative --input examples/models/part_skull.obj
```

Bash-оболочка по умолчанию использует `part_spinner.obj`. В PowerShell-оболочке путь по умолчанию `examples/models/part.obj` отсутствует: требуется передать существующую модель аргументом.

Для Qwen нужны переменные `QWEN_API_KEY`, `QWEN_BASE_URL`, `QWEN_VLM_MODEL`. Клиент загружает `.env` через python-dotenv и использует OpenAI-совместимый API. Значения и секреты в документацию не включаются; `.env` игнорируется Git.
